Findings

Every UX failure and gap in the register, open first, then by severity. A failure works against the reader; a gap is something the reader needs that is not there. Each status says when it was last checked, and on which version: nothing here claims to be current beyond that.

63 of 63 findings The address is the filter.

  • UX-001OpenHighFailure
    The first phone screen explains how the site is built, not what it is about

    newsroom.sgit.ai · First visit · Buried content, Builder chrome · obvious

    A contact who taps a link cannot tell in one screen that this is a publication about AI agents, security and publishing, or why they were sent it.

  • UX-002OpenHighFailure
    The home page is 59 phone screens long, with 845 links

    newsroom.sgit.ai · First visit · Overload · obvious

    The front page tries to show everything, so it chooses nothing for the reader. Nobody scrolls 59 screens; the curation is invisible.

  • UX-024OpenHighFailure
    All three rating scales start on 3

    newsroom.sgit.ai · Feedback · Preselected input · subtle

    Neither the reader nor the author can tell "not rated" from "useful". Every rating collected so far is ambiguous.

  • UX-025OpenHighGap
    Ratings never reach the author

    newsroom.sgit.ai · Feedback · Missing channel · silent

    The first contacts sent to the site teach the author nothing about what landed.

  • UX-029OpenHighFailure
    Opening an article charges a penny with no notice

    newsroom.sgit.ai · Money · Silent change, Unlabelled · subtle

    The first thing a new reader learns about the reading meter is that their balance dropped without being told.

  • UX-032OpenHighGap
    Nothing shows real money moving

    newsroom.sgit.ai · Trust · Missing signal · silent

    Readers and publishers asking "is this a real business?" find no answer.

  • UX-033OpenHighGap

    newsroom.sgit.ai · Trust · Missing signal · silent

  • UX-034OpenHighGap

    newsroom.sgit.ai · Trust · Missing channel · obvious

  • UX-037OpenHighFailure
    Two domains claim to be canonical for the same article

    newsroom.sgit.ai · Consistency · Inconsistent facts · silent

    Search engines split the article's standing between two copies, and readers can land on either.

  • UX-044OpenHighFailure
    The founder page says "the picks above" and no picks render on a phone

    newsroom.sgit.ai · Personas · Hidden until script, Dead end · intermittent

  • UX-046OpenHighFailure
    Setting location.hash inside a vault app re-navigates the frame: every link silently dead

    dev.vault.sgraph.ai · Platform · Host trap, Dead end · silent

    An app that works when opened as a file ships to readers with no working navigation, and nothing errors.

  • UX-056OpenHighFailure
    Scrolling back up a little puts focus in the address bar and opens the keyboard

    Firefox on iPad · Navigation · Focus hijack, Unexpected movement, Wrong culprit · intermittent

    The reader was not asking to go anywhere, and loses half the screen to a keyboard. Worse, it looks like the page has a bug: the first reading was that the site had somehow started an edit. The browser's fault is charged to the site, and the reader's concentration is broken either way.

  • UX-059OpenHighFailure
    A security prompt that asks you to approve a command it does not explain, and cuts off

    Claude app (iPhone and iPad) · Security decisions · Uninformed decision, Buried content, Missing signal · obvious

    The person is asked to make a security decision and given only code to make it with, partly hidden, on a phone. In practice the choice is to stop the work or to trust blindly, and every prompt like this teaches the habit of pressing Allow without reading, which defeats the point of asking. Here the command was harmless (a one-line edit to two files), but the prompt would have looked the same if it were not.

  • UX-060OpenHighFailure
    One unlabelled X throws away the whole recording, with no confirmation

    Claude app (iPhone and iPad) · Input and dictation · Data loss, Unlabelled · obvious

    A minute of dictation, often the hardest part of the message, is gone in one tap, on the button that looks least consequential. It has already happened to the reporter: "I literally fell for this in the past."

  • UX-063OpenHighFailure
    The live transcript sometimes stops while you are still speaking, and nothing says whether it is still recording

    Claude app (iPhone and iPad) · Input and dictation · Missing feedback, Data loss · intermittent

    The reader has to keep a mental check running while they speak, watching for words to appear, and stops trusting the tool whenever they do not. When it fails the recording cannot be recovered or resubmitted, so the loss is total.

  • UX-058OpenMediumFailure

Every attempt takes attention away from the text, which is the opposite of what hiding the toolbars is for.
